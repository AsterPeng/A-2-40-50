# ADR 0001: 以原始十进制文本保护测量值

状态：第 2 周开发设计，待正式 A-5 契约确认。需求：RQ-A-2-40。实际记录日期：2026-10-27。

## 决策与验收边界

本项目只从输入边界收到的已规范化 `TrackPoint` **原始测量值文本**开始负责。纬度、经度、高度和地速经验证后仍保存同一个字符串；构造 `TrackBatch`、JSON 往返和发送时不得用 JavaScript `number`、`toFixed`、舍入、截断或重新格式化改写它。字符串无法恢复上游此前已丢失的有效位，也不提高测量准确度。`DecimalString` 品牌类型只能表示通过本线验证的文本，不能用类型断言替代运行时验证。

## 语法和范围方案

- 开发草案语法为 `^-?(?:0|[1-9][0-9]*)(?:\.[0-9]+)?(?:[eE][+-]?[0-9]+)?$`。允许整数、小数、`e`/`E` 指数和负零；指数内部的正负号合法，数值开头的 `+` 不合法。拒绝空串、空白、前导零（`0` 除外）、`.5`、`1.`、`NaN`、`Infinity`、十六进制及任何非字符串测量值。语法只验证，不规范化字符。
- 合法示例：`113.918500123456789`、`12500.00`、`241.500`、`-0`、`-0.000e+2`、`1E-20`。`e`/`E`、指数符号及尾零均按输入保留。
- 坐标数值范围为纬度 `[-90, 90]`、经度 `[-180, 180]`。比较器应将符号、有效数字和十进制指数作为**文本表示的十进制数**处理：去掉仅用于比较的前导/尾随零，比较十进制数量级，再逐位比较同数量级的系数；不得先转为二进制浮点数，也不得生成新的保存值。零（包括负零）在比较时等于零，但原字符串不改变。
- 指数可能很大，比较器应避免按指数展开零或分配与指数值成比例的内存。对超长文本的资源上限如需设置，只能显式拒绝并记录为输入限制，不能静默截断；上限与正式 A-5 字节限制一起复核。高度和地速目前只验证语法，业务数值界限未获确认。
- 输入时间格式为带毫秒的 UTC ISO 8601 文本，验证真实日历值但不转换时区；字段与单位规范化属于上游，不在本项目补做。

## JSON 边界

外部输入和 `JSON.parse` 的结果均是 `unknown`。严格验证对象字段、类型、批次 `1..1000` 条、时间和十进制语法后，按契约字段顺序构造新对象并 `JSON.stringify`。序列化时测量值必须始终为 JSON 字符串；反序列化后再次验证，并逐字符比较四个测量值与输入。对象键顺序按草案输出稳定，航迹数组顺序不改变。`113.918500123456789`、尾零、指数和负零均在字符串往返中逐字符相等。

## 契约冲突闸口

[A5-Q11](../requirements/a5-open-questions.md) 尚未确认正式 A-5 是否接受 JSON 字符串。若正式契约只允许 JSON 数字，记录冲突并停止真实 A-5 精度验收声明，待双方确认可保留原始有效数字及字符要求的方案；客户端不得静默转成 JavaScript `number`。Mock 只验证本草案，不代表真实服务接受或持久化。
