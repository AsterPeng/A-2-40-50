# 需求基线（第 1 周）

项目需求号以用户指定的 `RQ-A-2-40` 和 `RQ-A-2-50` 为准。项目简报的十周表格及最终清单中出现 `RQ-A-1-40/50`，记为文档编号不一致，不能据此改变本项目范围。本文中的 A-5 HTTP 字段和行为均为开发草案，等待正式契约确认。

## RQ-A-2-40：测量值精度保护

### “最大浮点数精度”的验收解释

原始需求中的“保留最大浮点数精度”在本项目解释为：从本项目输入边界收到的**已规范化原始测量值文本**起，完整保留输入提供的有效数字及其字符表示，不因本项目的验证、保存、JSON 往返或发送再次损失精度。十进制语法只判定输入是否合法，不限制为 JavaScript `number` 可表示的位数，也不把合法值改写成另一种表示。字符保真不等于测量准确度提高：如果输入到达本项目前已转换为浮点数并丢失有效位，本项目不能还原那些数字，验收也不得声称已经还原。

正式 A-5 是否接受 JSON 字符串测量值仍待确认。若其契约要求 JSON 数字，应记录契约冲突并确认精度保障方案，不得静默转换为 JavaScript `number` 或宣称端到端精度验收通过。

1. 输入边界接收 `unknown`，验证后才构造领域类型；经纬度、高度和地速必须是十进制字符串。不得用 JavaScript `number`、`toFixed`、舍入或截断覆盖原始有效位。
2. 支持长小数、尾零、指数形式和负零，并保留通过验证的原始字符。拒绝 `NaN`、`Infinity`、十六进制、前导加号、非法字符和非字符串测量值。
3. 使用不损失精度的比较方法检查纬度 `[-90, 90]`、经度 `[-180, 180]`。高度和地速尚无正式业务范围，不自行增加上限或下限。
4. `TrackBatch` 的 JSON 验证、序列化、反序列化和 Mock 接收过程不得改变测量值字符。用 `113.918500123456789` 做端到端字符保真样例。

## RQ-A-2-50：A-5 客户端和 Mock

1. 经 `A5TrackClient` 端口执行单条或批量 `POST /v1/tracks`；单条写入也使用一条记录的 `TrackBatch`。请求体和响应均在边界验证，额外字段和缺失字段拒绝。批次 `1..1000` 条及幂等键 `1..128` 字符是待确认草案。
2. 验证 HTTP 202 全接收与部分拒绝：接收数加拒绝数等于请求数；拒绝索引是唯一、合法的请求数组整数索引。结构非法的 202 不算成功。
3. 400、409 为永久失败；429、503、网络错误和超时按策略有限重试；调用方取消立即停止。超时结果保留“未确认”语义，不能声称服务端未写入。
4. 同一语义批次的所有尝试复用相同请求体与幂等键。429 使用合法的 `Retry-After` 或退避策略。失败记录不得包含凭据、认证头、完整请求体或完整外部响应。
5. 本机回环地址的 Node HTTP Mock 覆盖全接收、部分拒绝、400、409、429、503、超时、取消和幂等重放/冲突；不模拟真实数据库。

## 验收层级与排除项

- **代码完成**：相应实现及自动测试通过。
- **本机离线验证完成**：干净环境可以复现检查、构建、测试和 Mock 演示。
- **真实 A-5 验收完成**：取得授权测试环境、正式契约及服务端接收、持久化和读回证据后才能声明。

本项目不负责数据抓取、供应商授权、VHHH 范围过滤、字段/单位/时间规范化、连续位置去重、A-5 服务端或数据库实现。外部确认项见 [A-5 问题清单](a5-open-questions.md)，测试方向见[追踪矩阵](traceability.md)。
