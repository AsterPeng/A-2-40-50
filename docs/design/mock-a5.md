# 本机 Mock A-5 设计（第 2 周）

状态：开发草案。实现计划在第 6 周，使用 Node.js 原生 `http`，仅绑定 `127.0.0.1` 并使用系统分配的端口。它模拟 HTTP 契约与幂等状态，不模拟真实 A-5 数据库、认证或持久化。

## 控制方式

测试通过创建 Mock 时传入场景配置和可注入时钟/延迟来选择行为，不向生产请求增加私有控制头。每个测试使用独立实例与内存状态，结束时关闭监听器、定时器和未完成连接。Mock 应保存供断言的请求原始字节，但只在进程内暴露给测试，不写日志或提交文件。

接收 `POST /v1/tracks`，检查路径、`Content-Type`、必填 `Idempotency-Key` 和 JSON 结构。四项测量值只允许字符串，不能通过 `number` 中转。请求中的额外字段、字段缺失或批次越界返回草案 400。若 A-5 正式规则不同，先改契约和测试，不能让 Mock 掩盖冲突。

## 场景与状态

| 场景           | Mock 行为                                     | 测试 ID     |
| -------------- | --------------------------------------------- | ----------- |
| 全接收         | 202，`acceptedCount=N`、`rejected=[]`         | IT-C-50-07  |
| 部分拒绝       | 202，配置合法拒绝索引并按计数守恒返回         | IT-C-50-08  |
| 请求无效       | 400 草案错误响应                              | IT-C-50-09  |
| 固定冲突       | 配置 409 错误模式                             | IT-C-50-10  |
| 限流           | 429，配置 `Retry-After`                       | IT-C-50-11  |
| 服务不可用     | 503；失败响应不占用幂等成功缓存               | IT-C-50-20  |
| 超时与取消     | 可控地延迟/保持响应；观察客户端终止并清理连接 | IT-C-50-21  |
| 同键同体重放   | 返回第一次缓存的 202 响应，不重新处理         | IT-C-50-22  |
| 同键异体       | 对已缓存的键及不同请求体字节返回 409          | IT-C-50-23  |
| 长小数字符保真 | 原始请求字节与解析后字符串逐字符核对          | CT-I3-A5-03 |

内存映射键为幂等键，值为**原始请求体字节**及成功响应。对已有键，先比较请求体字节；完全相同返回首次 202，任一字节不同返回 409。成功处理后才缓存，429/503 和未完成的超时不写成功缓存。部分拒绝的 202 是否应视为幂等重放结果属于正式契约待确认项；开发草案中缓存完整 202 响应。请求 ID 在重放时保持不变。Mock 的行为只用于本机离线验证，不能推断正式 A-5 的幂等窗口或落库状态。
