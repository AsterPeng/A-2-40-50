# A5TrackClient 设计说明（第 2 周）

状态：开发草案；第 4 周已实现正常写入与 202 校验，第 5 周已实现重试、超时、取消及脱敏失败记录。依据：[ADR 0001](../adr/0001-decimal-text-boundary.md)、[ADR 0002](../adr/0002-a5-write-semantics.md)、[OpenAPI 草案](../contracts/a5/openapi.yaml)和现有 `src/week-05/implementation/ports/a5-track-client.ts`。正式 A-5 地址、认证和 schema 均未确认。

## 模块边界与流程

`src/week-05/implementation/precision` 接受 `unknown`，验证并保存测量值原字符串；`src/week-05/implementation/a5-client` 只接受已验证 `TrackBatch`，但在运行时再次校验公开端口输入以防类型断言绕过。单条调用先包装成一条批次。所有额外字段、缺失字段、非字符串测量值、非法日期、非法批次大小都在发送前失败。配置包括基址、每次超时（默认 10 秒）、最大尝试数（默认含首次共 3 次）、基础退避（默认 1 秒）、最大等待（默认 30 秒）、是否重试超时（默认否）和受控依赖；真实基址不得作为默认值。

1. 在输入边界验证 `unknown`，返回有明确路径的验证错误；不转换单位、时间或测量值。
2. 按 `schemaVersion`、`tracks` 和 `TrackPoint` 草案字段顺序构造请求 JSON 一次；记录字节串，仅对它计算 SHA-256 幂等键。
3. 对每次尝试调用注入的 `fetch`（默认原生 `fetch`），同键、同体、同路径。将调用方取消与本次超时组合；请求结束清理监听器及计时器。
4. 以 `unknown` 解析响应 JSON，严格校验 202 结构、计数守恒和拒绝索引。仅在校验通过后返回 `accepted` 或 `partial`。
5. 根据分类决定是否等待重试；等待函数与时钟可注入，取消可中断等待。达到上限后返回最后失败类别、尝试数与未确认标志。
6. 输出最小脱敏诊断记录。日志不能包含响应 `message`、token、认证头、完整航迹或请求体。

## 端口复核项

端口可表达**本地验证失败**和**未列明 HTTP 状态**，并保留 HTTP 状态码。第 4 周实现了本地失败的 `attempts=0`、单次发送和严格 202 校验；第 5 周实现了 `attempts` 计数、有限重试和未确认状态传播。`uncertain` 反映请求可能已到达服务端而未获确认。`requestId` 仅从结构合法的 202 响应输出。网络异常、超时和请求中的取消不能作为已接收或明确未写入。

## 202 和失败决策

| 输入/响应                      | 输出或动作                           | 测试 ID            |
| ------------------------------ | ------------------------------------ | ------------------ |
| 单条或合法批次，202 且无拒绝   | `accepted`，`acceptedCount=N`        | IT-C-50-01、02     |
| 202，拒绝项非空且计数/索引合法 | `partial`，保留拒绝索引              | IT-C-50-14、30     |
| 202，字段/计数/索引非法        | 永久 `invalid-response`              | IT-C-50-25..27     |
| 本地批次无效                   | 不发送网络请求                       | IT-C-50-24、31     |
| 400 或 409                     | 永久失败，不重试或换键               | IT-C-50-03、04     |
| 429                            | 按合法 `Retry-After` 或退避有限重试  | IT-C-50-05、18、33 |
| 503 或网络错误                 | 有限退避重试                         | IT-C-50-06、16、19 |
| 超时                           | 未确认；按配置决定是否有限重试       | IT-C-50-12、32     |
| 调用方取消                     | 立即停止；不重试                     | IT-C-50-17、29     |
| 其他 HTTP 状态                 | 默认永久失败，保留状态码，不误判成功 | IT-C-50-28         |

`Retry-After` 按注入时钟解析，合法非负整数秒数或规范 GMT HTTP-date 在配置上限内等待。无效值回退到指数退避；随机扰动位于 0.5 至 1 倍，注入随机源可使测试固定结果。最大尝试数包含首次调用。超时后的重试仍可能遇到服务端已接收的第一次请求，因此必须复用幂等键；若最终失败，先前未确认状态继续保留。取消优先，且不得在等待或错误处理期间再发新请求。注入的等待函数即使忽略取消信号，客户端也会中断等待。

失败回调 `onFailure` 仅收到原因、尝试数、批次条数、未确认标志及可选 HTTP 状态；不会收到原始请求、响应或异常消息。回调自身抛错不改变写入结果。

## 精度兼容闸口

四项测量值的 JSON 类型为 `string`。若正式 A-5 只接受 JSON 数字，记录 [A5-Q11](../requirements/a5-open-questions.md) 契约冲突、暂停真实联调中的精度验收，并确认正式方案。不能将原字符串转为 JavaScript `number` 来迎合该接口，也不能把 Mock 的 202 作为端到端精度或落库证据。条件性测试 CT-I3-A5-04 检查这一闸口。
